# ROI-mask cache-coordination fix — read-only consumers

## Problem

`detection_cache_key(config, roi_mask)` folds `roi_mask` into the OBB detection cache
key ONLY when `config.obb.direct.slice.enabled AND roi_mask is not None`. The write path
(`InferenceRunner`) always passes `self._roi_mask` to `_open_caches`. Four read-only cache
consumers were reopening the cache via `_open_caches(config, cache_dir, video_sig)` with
NO mask argument, so for a sliced-inference + arena-ROI config they computed the pre-ROI
key and could never recognize the ROI-folded cache the main tracking pass wrote. This
failed safe (mismatched key => cache treated invalid, never stale-served) but silently
defeated the SAHI ROI tile-gating feature's own target configuration (every "compatible
cache found, reuse it" fast path was unreachable for sliced+ROI runs).

## The four sites

1. **`src/hydra_suite/core/tracking/ingest/frame_result_bridge.py:307`**
   `runner._caches = _oc(runner.config, runner.cache_dir)`
   → `runner._caches = _oc(runner.config, runner.cache_dir, runner._video_sig, runner._roi_mask)`
   Confirmed via grep of `core/inference/runner.py` that `self._video_sig` (set at
   `runner.py:493` via `video_signature(self._video_path)`) and `self._roi_mask` (set at
   `runner.py:489`/`967`) are the live attribute names, and that the runner's own
   `_open_caches` calls (lines 528, 543, 556, 574, 977, 1049) all already pass both.
   This also fixes a pre-existing, independent gap: the old call dropped `video_sig` too,
   which would mismatch the write-path key regardless of ROI.

2. **`src/hydra_suite/core/tracking/optimization/optimizer.py:563-568`**
   (`_open_and_validate_cache`, called from `TrackingOptimizer`)
   Added `_roi_mask = self.base_params.get("ROI_MASK", None)` and passed it as the 4th
   positional arg to `_open_caches`. Same `self.base_params` dict the class already reads
   `ROI_MASK` from elsewhere (line ~868/872), which is the params dict the write path
   (`DetectionCacheBuildWorker` / `InferenceRunner`, constructed via
   `build_inference_config_from_params`) is built from too.

3. **`src/hydra_suite/core/tracking/optimization/optimizer_workers.py:314-319`**
   (`run_tracking_preview`)
   Passed `params.get("ROI_MASK", None)` as the 4th positional arg to `_open_caches`
   (extracted inline at the call site; the function's existing
   `_roi_mask = params.get("ROI_MASK", None)` further down, used for preview filtering,
   is unchanged/untouched — both read the same `params` dict key).

4. **`src/hydra_suite/trackerkit/gui/orchestrators/config.py:3350-3355`**
   (`_find_or_plan_optimizer_cache_path._is_valid`, a UI cache-usability probe)
   The enclosing method already has `params: dict` (the method's own parameter) in scope
   at the `_open_caches` call. Passed `params.get("ROI_MASK", None)` as the 4th arg — same
   pattern, same key, no new plumbing needed. All four sites are fixed; none needed to be
   left undone.

## Mask source matches the write path

All four sites now source the mask from the exact same place the write path draws it
from: `runner._roi_mask` (site 1, identical object the runner itself uses) or
`params["ROI_MASK"]` / `self.base_params["ROI_MASK"]` (sites 2-4, the raw native-resolution
mask stored in the params dict that `build_inference_config_from_params` / the
`InferenceRunner` constructor both read `ROI_MASK` from to set `self._roi_mask`). No
resizing/transform was introduced — the raw mask is passed through unchanged, so its
content hash (see `detection_cache_key` → `_param_repr(roi_mask)`) matches the write-side
key byte for byte.

## Test: RED → GREEN evidence

Added to `tests/test_inference_cache_keys.py`:

- `test_open_caches_sliced_roi_write_and_consumer_keys_now_agree` — **GREEN**. For a
  sliced+ROI `InferenceConfig`, calling `_open_caches(cfg, dir, sig, mask)` twice (once
  representing the write path, once the now-fixed consumer) yields an IDENTICAL
  `detection.key`.

- `test_open_caches_sliced_roi_old_consumer_behavior_mismatched_key` — **RED**, documents
  the bug that existed. For the same sliced+ROI config, the write path's key
  (`_open_caches(cfg, dir, sig, mask)`) is compared against the OLD buggy consumer call
  pattern (`_open_caches(cfg, dir, sig)`, mask omitted) and the two keys are asserted
  DIFFERENT — reproducing exactly the coordination gap that made the four sites above
  fail to recognize the ROI-folded cache.

- `test_open_caches_non_sliced_key_unchanged_with_or_without_mask` — byte-parity guard.
  For a config with `SliceConfig(enabled=False)`, `_open_caches` with vs. without the
  mask produces the SAME `detection.key` — confirming the fix is a no-op for every
  existing (non-sliced) call site.

These sit alongside the pre-existing, more granular `detection_cache_key`-level ROI tests
in the same file (`test_roi_folds_into_key_only_when_slicing_enabled_and_mask_present`,
`test_roi_ignored_when_slicing_disabled_key_is_byte_identical`, etc.), which already
proved the underlying key function's behavior; the new tests prove the *consumer
plumbing* now actually uses it correctly.

## Non-sliced / no-ROI parity confirmation

Confirmed both at the `detection_cache_key` level (pre-existing test
`test_roi_ignored_when_slicing_disabled_key_is_byte_identical`) and at the `_open_caches`
level (new test `test_open_caches_non_sliced_key_unchanged_with_or_without_mask`): for a
non-sliced or no-ROI config, passing the mask through unconditionally to `_open_caches`
never changes the resulting key. No conditionals were added to gate the mask-passing on
`slice.enabled` — the fix is unconditional at every call site, matching the task's stated
correctness criterion, and relies solely on `detection_cache_key`'s own internal gating.

## Regression fixture updates

Three existing tests monkeypatched `_open_caches`/`_fake_open_caches` with a fixed 3-arg
signature (`cfg, cache_dir, video_sig`); after threading the 4th `roi_mask` arg through
`optimizer_workers.py`, these fakes needed a `roi_mask=None` optional 4th parameter to
keep accepting the real call:

- `tests/test_optimizer_workers_core.py` — `_patch_cache_open`'s lambda (used by 2 tests)
  and the "missing cache" test's lambda.
- `tests/test_tracking_preview_worker_cache.py` — `_fake_open_caches` (now also records
  `calls["roi_mask"]`, unused by assertions but available for future tightening).

No production call sites' behavior needed test-only workarounds beyond this signature
widening.
