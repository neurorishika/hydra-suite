    Environments and Makefile Reference¶

    This page explains how a HYDRA environment is put together and lists the Makefile targets. To install, follow Installation: python install.py does everything described here.

    Where each dependency comes from¶

    Layer Source of truth What it provides
    Conda env (optional) environment.yml, environment-mps.yml, environment-cuda.yml (mirrored by CONDA_PACKAGES in install.py) Only python, pip, git, cmake, c-compiler, cxx-compiler (Windows: pip, git, cmake). No Qt, no OpenCV, no ffmpeg, no CUDA libraries.
    Python dependencies pyproject.toml The only place Python packages are declared: core dependencies plus the cpu, mps, cuda12, cuda13 tier extras and the sam, dev, docs feature extras.
    Tested versions constraints/base.txt, constraints/cuda12.txt, constraints/cuda13.txt Exact versions applied by default, so results do not drift with upstream releases. Generated by tools/lock_constraints.py.
    torch / torchvision TORCH_VERSION / TORCHVISION_VERSION in install.py A pinned pair, installed from the PyTorch wheel index for the tier (cpu, cu128, cu130; PyPI on macOS).
    ffmpeg binary imageio-ffmpeg wheel (core dependency) Bundled ffmpeg on every platform. A system ffmpeg on PATH takes precedence. Conda's ffmpeg is deliberately not used: its harfbuzz/freetype libraries broke Qt on Rocky Linux 9 (undefined symbol: FT_Get_Colorline_Stops).
    Git-only installs install.py The ultralytics CLIP fork (SAM3 text encoder) and the Kronauer lab AprilTag fork, each pinned to a commit.

    There are no requirements*.txt files any more. If a package is imported by src/, it must be declared in pyproject.toml (tests/test_dependencies_declared.py enforces this).

    Environments¶

    Env Tier Created by
    hydra cpu python install.py on a CPU host, or make setup
    hydra-mps mps python install.py on Apple Silicon, or make setup-mps
    hydra-cuda cuda (12 or 13) python install.py on an NVIDIA host, or make setup-cuda
    hydra-sam3 sidecar python install.py --with-sam3-train (CUDA only)
    sleap sidecar python install.py --with-sleap

    Without conda, install.py creates a venv at <checkout>/.venv-<name> instead (sidecars need conda).

    Sidecar environments¶

    Two features need dependencies that cannot coexist with the main env, so they run in separate conda envs that HYDRA launches as subprocesses:

    • hydra-sam3 holds Meta's sam3 training code, which pins numpy<2. It gets the same hydra-suite source as the main env (editable checkout, git commit or wheel). See SAM3 training.
    • sleap holds sleap==1.6.2 (which brings sleap-nn 0.1.x) with the torch build matching the host. See Integrations.

    GPU library loading (CUDA)¶

    ONNX Runtime GPU and TensorRT load the CUDA user-space libraries from the nvidia-* pip wheels, via onnxruntime.preload_dlls(). No conda CUDA packages are installed and no LD_LIBRARY_PATH activation hook is written. This works the same way on Linux and Windows. Each CUDA major gets exactly one wheel family:

    CUDA torch wheels ONNX Runtime GPU TensorRT / CuPy
    12 +cu128 onnxruntime-gpu[cuda,cudnn] >=1.24,<1.27 (nvidia-*-cu12 wheels) tensorrt-cu12*, cupy-cuda12x
    13 +cu130 onnxruntime-gpu[cuda,cudnn] >=1.28 (the same nvidia-* wheels torch +cu130 uses) tensorrt-cu13*, cupy-cuda13x

    The installer removes the other family's onnxruntime/TensorRT packages before installing. Mixing families in one env breaks cuDNN loading, and hydra doctor detects it.

    Makefile targets¶

    Every install target is a thin wrapper around install.py. Windows users run install.py directly.

    Create a conda env (step 1)¶

    make setup            # CPU          -> hydra
make setup-mps        # Apple Silicon -> hydra-mps
make setup-cuda       # NVIDIA       -> hydra-cuda

    These only create the env (install.py --create-only).

    Install into the activated env (step 2)¶

    make install          # CPU
make install-mps      # Apple Silicon
make install-cuda     # NVIDIA; CUDA 12/13 auto-detected from the driver
make install-cuda CUDA_MAJOR=12   # optional override

    These run install.py --target current with the activated env's Python.

    Update or remove¶

    make env-update       # or env-update-mps / env-update-cuda  (install.py --update)
make env-remove       # or env-remove-mps / env-remove-cuda

    To rebuild an env from scratch, use python install.py --recreate.

    Individual steps and checks¶

    make doctor                  # hydra doctor
make install-apriltag-fork   # install.py --only apriltag
make install-sam3-clip       # install.py --only clip
make configure-mps-libs      # python -m hydra_suite.runtime.macos_libomp
make configure-cuda-ort      # retired; now just runs hydra doctor --tier cuda

    Optional sidecars and tools¶

    make setup-sam3-train  # install.py --with-sam3-train  (CUDA only)
make setup-sleap       # install.py --with-sleap
make install-dev       # [dev] extra, with the tested pins
make docs-install      # [docs] extra, with the tested pins

    Other useful targets¶

    make help              # Full command catalog
make pytest            # Run tests
make format            # Format code (autopep8 → black → isort)
make lint              # Lint at moderate severity
make build             # Build wheel and sdist

    Fresh-box conda/mamba initialisation (non-interactive shells)¶

    Two things a first-time provisioning session must get right that are easy to miss because they only bite in a non-interactive shell (e.g. a spawned subprocess, ssh host 'cmd', or a service worker) rather than an interactive login shell:

    1. conda's init block must sit above Ubuntu's interactivity guard in ~/.bashrc — the guard is the line that looks like case $- in *i*) ;; *) return;; esac. If conda's >>> conda initialize >>> block is below that guard, a non-interactive shell returns before conda ever gets onto PATH. The SLEAP service launches conda run -n sleap from exactly such a shell; if conda is unreachable there, the run does not error loudly — it produces empty CSVs, which then falsely compare as EQUIVALENT against a baseline in tools/equivalence/. Verify with ssh <host> 'conda run -n sleap python -c "import sleap"' — no source ~/.bashrc first — to prove the non-interactive path actually works.
    2. MAMBA_ROOT_PREFIX must be set before mamba.sh is sourced. Without it, mamba prints an 11-line WARNING block to stdout on every non-interactive shell invocation. This is invisible in an interactive terminal but corrupts the SAM3 sidecar's stdout protocol, which parses the child process's stdout line-by-line for @@HYDRA_SAM3_PROGRESS@@ records.

    Both were found missing on a from-scratch Ubuntu box during provisioning (2026-09-07); the fix is in ~/.bashrc, not in this repo, since it's a per-machine shell-init concern.

    Hugging Face authentication for SAM3¶

    The stock SAM3 weights (facebook/sam3) are licence-gated. Any machine that downloads them (for escalation) or trains SAM3 needs a one-time login from an account that has accepted the licence at https://huggingface.co/facebook/sam3:

    hf auth login      # or: export HF_TOKEN=... / HUGGING_FACE_HUB_TOKEN=...

    For training this is required even when a local sam3.pt is present: build_sam3_image_model fetches the model config from the gated repo at build time. src/hydra_suite/training/sam3_lora/preflight.py checks for a credential up front and refuses with a message that names the fix (hf auth login). If you see a bare GatedRepoError: 401 instead, you are hitting the credential check too late in the pipeline; file that as a regression.
